# Восстановление кодировки (CP866 mojibake)

> Doc-ID: FIX-ENCODING-1 | Дата: 2026-06-21 | Связанные: [MCP-OCDB-2], [REF-ENCODING-1]

## 1. Проблема

В базах opencode встречаются сессии с **испорченными заголовками (title)** — русский текст отображается как набор иероглифов:

```
╨Р╤Г╨┤╨╕╤В docs: ╤Б╤В╤А╤Г╨║╤В╤Г╤А╨░ ╨╕ ╨║╨╛╨╜╤В╨╡╨╜╤В (@explore subagent)
```

Вместо читаемого:

```
Аудит docs: структура и контент (@explore subagent)
```

### 1.1 Причина

UTF-8 байты русского текста были **прочитаны как CP866 (DOS Cyrillic)** и сохранены в БД как Unicode.

Например, буква **А** (U+0410) в UTF-8 кодируется байтами `D0 90`:
- Байт `D0` (208) → в CP866 это символ `╨` (U+2568)
- Байт `90` (144) → в CP866 это символ `Р` (U+0420)
- В БД сохранилась строка `╨Р` вместо `А`

### 1.2 Где встречается

- `session.title` — заголовки сессий (наиболее часто)
- `message.content` — содержимое сообщений (теоретически возможно)

## 2. Инструменты MCP

В MCP-сервер `mcp-opencode-db.py` добавлены два инструмента:

### 2.1 `oc_detect_mojibake`

Сканирует таблицу `session` на предмет CP866 mojibake.

**Параметры:**
| Параметр | Тип | Описание |
|----------|-----|----------|
| `db` | string | Имя БД (по умолч. `opencode.db`) |

**Пример:**
```json
{
  "database": "opencode.db",
  "tables_scanned": ["session"],
  "total_affected": 48,
  "issues": [
    {
      "id": "ses_181c5eee...",
      "table": "session",
      "original": "╨Р╤Г╨┤╨╕╤В docs: ╤Б╤В╤А╤Г╨║╤В╤Г╤А╨░ ...",
      "decoded": "Аудит docs: структура и контент ..."
    }
  ]
}
```

### 2.2 `oc_fix_mojibake`

Исправляет mojibake в заголовках сессий. Деструктивная операция — требует `confirm=true`.

**Параметры:**
| Параметр | Тип | Описание |
|----------|-----|----------|
| `db` | string | Имя БД (по умолч. `opencode.db`) |
| `confirm` | boolean | Подтверждение (обязательно) |
| `dry_run` | boolean | Предпросмотр без изменений |
| `table` | string | `session` (по умолч.), `message`, `part`, `all` |

**Пример (dry-run):**
```json
{
  "db": "opencode.db",
  "dry_run": true
}
```

**Пример (реальное исправление):**
```json
{
  "db": "opencode.db",
  "confirm": true
}
```

## 3. Алгоритм восстановления

### 3.1 Детекция

Строка считается mojibake, если:
1. Содержит символы из блока Box Drawing (U+2500-U+257F) — например, `╨`, `╤`, `╥`
2. Содержит кириллические символы из CP866 (U+0400-U+04FF)
3. Результат декодирования через CP866→UTF-8 отличается от исходной строки
4. Результат содержит кириллицу (U+0400-U+04FF)

### 3.2 Декодирование

Каждый Unicode-символ mojibake-строки конвертируется обратно в CP866-байт через lookup-таблицу:

```
╨ (U+2568) → 0xD0
Р (U+0420) → 0x90
```

Полученная последовательность байт декодируется как UTF-8:

```
[0xD0, 0x90] → "А"
```

ASCII-символы (0x20-0x7E) проходят без изменений.

### 3.3 CP866 Lookup-таблица

```python
_CP866_MAP = {
    # Заглавные А-Я (0x80-0x9F)
    0x0410: 0x80, 0x0411: 0x81, ..., 0x042F: 0x9F,
    # Строчные а-п (0xA0-0xAF)
    0x0430: 0xA0, 0x0431: 0xA1, ..., 0x043F: 0xAF,
    # Псевдографика (0xB0-0xDF)
    0x2591: 0xB0, 0x2502: 0xB3, 0x2524: 0xB4,
    0x2568: 0xD0, 0x2564: 0xD1,
    # Строчные р-я (0xE0-0xEF)
    0x0440: 0xE0, 0x0441: 0xE1, ..., 0x044F: 0xEF,
    # Прочее (0xF0-0xFF)
    0x0401: 0xF0, 0x0451: 0xF1, ..., 0x00A0: 0xFF,
}
```

def decode_mojibake(text: str) -> str:
    """Reverse CP866 mojibake to original UTF-8 text."""
    if not text:
        return text
    buf = bytearray()
    for ch in text:
        cp = ord(ch)
        if 0x20 <= cp <= 0x7E:
            buf.append(cp)
        elif cp in CP866_MAP:
            buf.append(CP866_MAP[cp])
        else:
            buf.append(0x3F)
    return buf.decode("utf-8", errors="replace")


def fix_database(db_path: str, dry_run: bool = True):
    """Scan and fix mojibake in all session titles."""
    conn = sqlite3.connect(db_path)
    conn.execute("PRAGMA journal_mode=WAL")

    rows = conn.execute("SELECT id, title FROM session").fetchall()
    affected = []

    for sid, title in rows:
        if not title:
            continue
        decoded = decode_mojibake(title)
        if decoded != title and any(0x0400 <= ord(c) <= 0x04FF for c in decoded):
            affected.append({"id": sid, "original": title[:100], "decoded": decoded[:100]})
            if not dry_run:
                conn.execute("UPDATE session SET title = ? WHERE id = ?", (decoded, sid))

    if not dry_run:
        conn.commit()

    conn.close()
    return affected

## 6. Предотвращение

Чтобы избежать mojibake в будущем:

1. **Убедитесь, что SQLite база сохраняется в UTF-8**
2. **Не открывайте .db файлы в редакторах с автоопределением кодировки** (Notepad, Notepad++)
3. **При экспорте в JSON добавляйте BOM** (U+FEFF):
   ```python
   json.dumps(data, ensure_ascii=False) + "\n"
   ```
4. **Проверяйте кодировку при импорте данных из внешних источников**

## 7. Диагностика

Быстрый SQL-запрос для поиска mojibake:

```sql
SELECT id, title FROM session
WHERE title LIKE '%╨%' OR title LIKE '%╤%' OR title LIKE '%╥%';
```

Характерные признаки mojibake:
- Наличие символов `╨`, `╤`, `╥`, `╗`, `║` (Box Drawing, U+2500+)
- Текст содержит смесь псевдографики и кириллицы
- После декодирования появляется осмысленный русский текст
